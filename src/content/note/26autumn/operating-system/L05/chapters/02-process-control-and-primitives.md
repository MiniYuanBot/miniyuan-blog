# 02 进程控制与原语

[本讲目录](../index.md) · [课程目录](../../index.md) · [上一节：01 进程表与队列模型](01-process-table-and-queue-model.md) · [下一节：03 fork、exec 与写时复制](03-unix-fork-exec-and-copy-on-write.md)

> [!abstract] 本节要点
> - 进程控制操作完成进程各状态之间的转换，由具有特定功能的原语完成：创建、撤销、阻塞、唤醒、挂起、激活、改变优先级等；有某个状态才需要对应的原语。
> - 原语（primitive）即原子操作（atomic）：完成特定功能的一段程序，不可分割、不可中断，执行必须连续；主要实现手段是先关中断、执行完再开中断。
> - 创建进程最基本的三件事：分配唯一 PID、分配 PCB、分配（虚拟）地址空间；随后初始化 PCB（状态为 New 等）、设置队列指针、创建或扩充其他数据结构。
> - 撤销进程：结束子进程或线程、回收资源（文件、网络连接、内存）、撤销 PCB；阻塞由进程自己执行阻塞原语，与唤醒成对出现。
> - 先分清 API 体系：UNIX/Linux 用 `fork`/`exec`、`exit`、`wait`；Windows 用 `CreateProcess`、`ExitProcess`、`WaitForSingleObject`。

## 进程控制与原语（Primitive）

[上一节](01-process-table-and-queue-model.md)说明了状态转换需要触发条件；条件出现后，总要有一段代码真正去改 PCB、挪队列。对进程的所有控制最终都落在一个个函数上。

**进程控制**是完成进程各状态之间转换的操作，它由具有特定功能的原语完成，常见的有：[^s2p39]

- 进程创建原语
- 进程撤销原语
- 阻塞原语
- 唤醒原语
- 挂起原语
- 激活（解挂）原语
- 改变进程优先级
- ……

有某个状态，才有相应的控制函数。本课程采用五状态模型，没有挂起状态，因此也就没有挂起和激活原语；反过来，如果系统想支持动态提升或降低优先级，就必须提供相应的函数。[^s4b2]

### 原语的定义

**原语**（primitive）也称**原子操作**（atomic），是完成某种特定功能的一段程序，具有不可分割性或不可中断性：原语的执行必须是连续的，执行过程中不允许被中断。[^s2p39]

“不可分割”指的是不能执行到一半停下来、过一会儿再接着执行。为什么进程控制必须如此？以阻塞原语为例：它要把当前进程状态改为阻塞、把 PCB 从运行位置摘下并链入等待队列。如果改完状态还没链入队列时被打断，另一段代码看到的就是一个“状态写着阻塞、却不在任何等待队列里”的 PCB，事件发生时也就无人唤醒它。

“原子”这个名字来自当时的认识：原子被认为是最小、不可再分的粒子。[^s4b2]

### 用关中断实现原语

实现原语最重要的手段是**关中断**（disable interrupt）：进入这段代码前关闭中断，不响应任何中断；执行完再**开中断**（enable interrupt）。[^s4b2]

```c
/* 原语的示意结构，函数名仅为示意 */
disable_interrupt();   /* 关中断：此后不会被中断打断 */
/* 修改 PCB 状态、调整队列指针等 */
enable_interrupt();    /* 开中断 */
```

这样做有效的原因是：单处理器上，当前代码只有在中断（包括时钟中断）发生时才可能被夺走 CPU，关掉中断就消除了被打断的机会。

> [!note] 补充解释
> 关中断只对当前 CPU 有效。在多处理器上，其他 CPU 仍可能同时修改同一个队列，所以实际内核还要配合自旋锁等同步机制。这部分属于后续同步互斥的内容，这里只需理解原语“不可中断”的要求和关中断这一基本手段。

## 进程何时创建、何时终止

进程有生命周期：从无到有，再从有到无。[^s2p40]

**进程何时创建**：

1. 系统初始化时（系统启动会创建一批进程）；
2. 操作系统提供的服务（服务本身以进程或线程的形式存在）；
3. 交互用户登录系统（登录成功后出现一个新的 shell 进程直接面对用户）；
4. 由现有的进程派生出一个新进程（如 `fork`）；
5. 提交一个程序执行（例如在命令行输入命令后回车）。

**进程何时终止**：

| 终止方式 | 是否自愿 |
| --- | --- |
| 正常退出 | 自愿 |
| 出错退出 | 自愿 |
| 严重错误 | 非自愿 |
| 被其他进程杀死 | 非自愿 |

渠道不同，结果一样：进程不能再执行。导致进程终止的具体事件包括：正常结束；给定时限到；缺少内存；存储器出界；保护性出错（如写只读文件）；算术错；超出时间（进程等待某事件超过最大值）；I/O 失败；无效指令（如试图执行数据）；特权指令；操作系统干预（如发生死锁时）；父进程请求中止某一子进程；父进程中止（子进程也随之中止）。[^s2p40]

其中不少事件就是异常（存储器出界、算术错、特权指令、无效指令），这再次说明中断/异常是状态转换的触发条件。

## 进程创建的基本工作

创建原语在 UNIX 中对应 `fork`/`exec`，在 Windows 中对应 `CreateProcess`。不管是哪个体系，创建一个进程都要做以下工作：[^s2p41]

1. **分配唯一标识 PID**：相当于给新进程发一个学号。
2. **分配进程控制块 PCB**：一个大数据结构，相当于建立学籍档案。
3. **分配地址空间**：只要创建进程就必须有地址空间，这里分配的是虚拟地址空间，内容将来放在物理内存的哪里以后再定。
4. **初始化 PCB**：填入默认值，例如状态为 New 等。
5. **设置相应的队列指针**：例如把新进程加入就绪队列的链表。
6. **创建或扩充其他数据结构**。

前三件是最核心的；PID、PCB、地址空间都有了，剩下的填表、挂队列就好办了。[^s4b2]

```mermaid
flowchart LR
  A["分配 PID"] --> B["分配 PCB"] --> C["分配虚拟地址空间"]
  C --> D["初始化 PCB（状态 New 等）"] --> E["设置队列指针（入就绪队列）"] --> F["创建或扩充其他数据结构"]
```

UNIX 如何把这些步骤拆进 `fork` 和 `exec`，以及 Linux 怎样优化地址空间的复制，见[fork、exec 与写时复制](03-unix-fork-exec-and-copy-on-write.md)。

## 进程撤销、阻塞与唤醒

**进程撤销**要做三件事：[^s2p42]

1. 结束子进程或线程；
2. 收回进程所占有的资源：关闭打开的文件、断开网络连接、回收分配的内存……；
3. 撤销该进程的 PCB。

对应的系统调用：UNIX 为 `exit`，Windows 为 `ExitProcess`。

**进程阻塞**：处于运行态的进程在运行过程中期待某一事件发生，例如等待键盘输入、等待磁盘数据传输完成、等待其他进程发送消息。当被等待的事件尚未发生时，**由进程自己执行阻塞原语**，使自己由运行态变为阻塞态。[^s2p43]

**进程唤醒**与阻塞成对出现。[^s4b2] 所等事件发生后，由发现事件的一方（例如处理 I/O 完成的代码）执行唤醒原语，把进程从等待队列移入就绪队列（对应队列模型中“事件发生，移进就绪队列”的那条边）。

与阻塞、等待对应的调用：UNIX 为 `wait`，Windows 为 `WaitForSingleObject`。`wait` 让调用者一直等到另一个进程（通常是子进程）结束。[^s2p43]

> [!warning] 易错点
> 阻塞是进程**主动**执行的（自己发现要等的事件还没发生），唤醒则一定由**别人**完成：一个已经阻塞的进程不在 CPU 上运行，不可能自己唤醒自己。

## 认清所在的 API 体系

同一个概念在不同系统里有不同的接口，学习时一定要知道自己处在哪个 API 体系下。本课程基本按 UNIX/Linux 体系（包括 FreeBSD 等）讲解，Windows 是另一套。[^s4b2]

| 操作 | UNIX/Linux | Windows |
| --- | --- | --- |
| 创建 | `fork` / `exec` | `CreateProcess` |
| 撤销 | `exit` | `ExitProcess` |
| 等待 | `wait` | `WaitForSingleObject` |

> [!question]- 自测：某内核的阻塞原语分两步：①把 PCB 状态改为“阻塞”；②把 PCB 链入磁盘等待队列。如果没有关中断，在①②之间发生磁盘完成中断，会出现什么问题？
> 中断处理程序去磁盘等待队列找要唤醒的进程，但这个 PCB 还没链进去，于是找不到它；等中断返回后②才执行，进程进入等待队列，而它等的事件已经发生过了，可能再也没人唤醒它。用关中断把①②变成原语，就排除了这种中间状态。

> [!question]- 自测：一个进程执行时访问了越界地址，最终被终止。它属于哪种终止方式，触发这次状态转换的是什么？
> 属于“严重错误（非自愿）”终止，对应终止事件中的“存储器出界”。触发条件是 CPU 产生的访存异常，内核在异常处理中调用撤销原语，回收资源并撤销 PCB。
