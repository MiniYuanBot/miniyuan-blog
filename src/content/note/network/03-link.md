## 1. 数据链路层概述

### 1.1 网络体系结构中的位置

**OSI七层模型** vs **TCP/IP四层模型** vs **五层协议模型**

```
应用层        应用层
表示层        运输层 (TCP/UDP)
会话层        网际层 IP
运输层    →   网络接口层
网络层        (数据链路层+物理层)
数据链路层    
物理层        
```

**数据链路层的核心地位：**
- 实现**相邻结点**之间的通信
- 网络中的主机、路由器、交换机等都必须实现数据链路层
- 不同链路可采用不同的数据链路层协议

### 1.2 基本术语

| 术语 | 定义 |
|------|------|
| **结点(node)** | 主机、路由器等网络设备 |
| **链路(link)** | 连接相邻结点之间的信道（有线/无线） |
| **帧(frame)** | 数据链路层传输的基本单位 |

### 1.3 信道类型

| 类型 | 特点 | 协议要求 |
|------|------|----------|
| **点对点信道** | 一对一通信 | 简单，无需协调 |
| **广播信道** | 一对多通信 | 需要专用共享信道协议协调发送 |

### 1.4 链路层功能

- **链路管理**：建立、拆除连接（面向连接服务时）
- **成帧/解帧**：将数据封装为帧
- **流量控制**：控制发送数据量
- **差错控制**：实现无差错传送
- **透明传输**：区分数据信息和控制信息
- **寻址**：标识收发双方

### 1.5 实现位置：网络适配器（网卡）

```
┌─────────────────────────────────────┐
│  application                        │
│  transport                          │
│  network                            │
│  link ←─────────────────────────┐   │
│  physical                       │   │
│      │                          │   │
│  host bus (e.g., PCI)           │   │
│      │                          │   │
│  ┌─────────────────┐            │   │
│  │  network        │←───────────┘   │
│  │  adapter card   │ controller     │
│  │  (NIC)          │ physical       │
│  └─────────────────┘ transmission   │
│      ↑                              │
│  串/并变换、数据缓存、链路层功能实现      │
└─────────────────────────────────────┘
```

**网卡功能：**
- 发送端：封装成帧、添加校验位和地址、流量控制
- 接收端：检错、地址检查、流量控制、提取数据交高层

> **IP与MAC的关系**：IP地址由网络层使用，MAC地址由链路层使用。ARP协议负责IP到MAC的地址解析。

## 2. 成帧与透明传输

### 2.1 成帧方法

| 方法 | 原理 | 特点 |
|------|------|------|
| **字节计数法** | 头部字段标识帧字节数 | 头部出错则失步 |
| **固定帧长度** | 如RS232，固定字符长度 | 简单，效率低 |
| **控制字符法** | 特殊字符SOH/EOT定界 | 需处理透明传输 |
| **比特填充法** | 标志位+零比特填充 | 如HDLC、PPP |

### 2.2 透明传输解决方案

**字节填充（Character Stuffing）**
- 数据中出现`SOH`或`EOT`前插入转义字符`ESC`（0x1B）
- 数据中出现`ESC`前再插入一个`ESC`
- 接收端删除插入的转义字符

```
原始数据: [SOH][A][EOT][B][SOH]
发送数据: [SOH][A][ESC][EOT][B][ESC][SOH][EOT]
```

**零比特填充（Bit Stuffing）**
- 标志字段F = `01111110`
- 发送端：发现5个连续1，立即填入一个0
- 接收端：发现5个连续1，删除后面的0

```
原始数据: 01111110 (恰好为标志位)
发送数据: 011111010 (5个1后填0)
```

### 2.3 以太网帧结构（V2）

```
┌─────────┬─────────┬─────────┬────────┬─────────┬─────────┐
│ 前同步码 │ 目的地址 │ 源地址  │  类型   │  数据   │   FCS   │
│  8字节  │  6字节  │  6字节  │ 2字节  │46~1500B │  4字节  │
└─────────┴─────────┴─────────┴────────┴─────────┴─────────┘
        ↓
   7字节同步 + 1字节帧开始定界符(10101011)
```

**关键字段：**
- **类型字段**：标识上层协议（0x0800=IP，0x0806=ARP）
- **FCS**：帧校验序列（CRC校验）
- **MTU**：最大传送单元1500字节

## 3. 差错控制

### 3.1 差错类型与检测

- **误码率 Pb** = 误码位数 / 发送总位数
- **无差错帧概率** P1 = (1-Pb)^L （L为帧长）

### 3.2 差错检测方法

| 方法 | 类型 | 能力 |
|------|------|------|
| **奇偶校验** | 检错码 | 检测单比特错 |
| **二维奇偶校验** | 检错/纠错码 | 检测并纠正单比特错 |
| **汉明码** | 纠错码 | 纠正单比特错，检测双比特错 |
| **CRC循环冗余校验** | 检错码 | 检测突发错，效率高 |
| **校验和** | 检错码 | IP/TCP/UDP使用 |
| **交织码** | 检错码 | 将突发错转为随机错 |

### 3.3 CRC循环冗余校验（重点）

**原理：**
- 数据位D（d位）+ 冗余位R（r位）构成码字
- 选择生成多项式G（r+1位）
- 发送端：使<D,R>能被G整除（模2运算）
- 接收端：<D,R>除以G，余数为0则无错

**计算过程：**
```
数据D = 1010001101 (d=10位)
生成式G = 110101 (r+1=6位，即r=5)

计算：2^5 × D ÷ G 得余数R
      101000110100000 ÷ 110101 = 商...余数01110

发送数据：1010001101 01110 (D后附加R)
```

**典型生成多项式：**
- CRC-16：X^16 + X^15 + X^2 + 1
- CRC-CCITT：X^16 + X^12 + X^5 + 1
- CRC-32：用于以太网

**CRC特点：**
- 能检出所有1比特错、2比特错、奇数位错
- 能检出所有≤r位的突发错
- 易于硬件实现（移位寄存器）

### 3.4 码距与编码效率

- **码距**：两个码字中不相同位的个数
- **检错能力**：要检测d位错，需码距≥d+1
- **纠错能力**：要纠正d位错，需码距≥2d+1
- **码率** = m/n（m位信息，n位码长）

> **重要区分**：CRC只能实现"无差错接受"（丢弃错误帧），不能实现"可靠传输"。可靠传输需要确认和重传机制（ARQ）。

## 4. 可靠传输与流量控制

### 4.1 停等协议（Stop-and-Wait）

**工作原理：**
```
发送方A          接收方B
   │                │
   ├─发送M1────────→│
   │←────确认M1─────┤ (收到ACK后发送M2)
   ├─发送M2────────→│
   │←────确认M2─────┤
```

**关键机制：**
- **超时重传**：发送后启动定时器，超时未收到确认则重传
- **序号机制**：数据帧和确认帧都带1比特序号（0/1交替）
- **重复帧处理**：接收方丢弃重复帧，重传确认

**信道利用率：**
```
U = tf / (tf + 2tp) = 1 / (1 + 2α)

其中：α = tp/tf = (传播时延)/(发送时延)
```

**性能问题**：长时延信道利用率低（如卫星通信）

### 4.2 连续ARQ协议（Go-Back-N）

**滑动窗口机制：**
- 发送窗口WT：可连续发送的帧数
- 接收窗口WR = 1：只接收按序到达的帧
- 累计确认：ACK i 表示确认i-1及之前所有帧

**工作流程：**
```
发送窗口=5：[0,1,2,3,4]可发送
收到ACK2后：窗口滑动至[2,3,4,5,6]
若帧2丢失：从帧2开始重传所有已发帧（回退N）
```

**发送窗口最大值**：WT ≤ 2^n - 1（n为帧序号比特数）

### 4.3 选择重传ARQ（Selective Repeat）

**特点：**
- 接收窗口WR > 1，可接收乱序但落在窗口内的帧
- 只重传出错或丢失的帧，不重传已正确接收的帧
- 需要接收端缓存

**窗口限制**：WR ≤ 2^(n-1) = 2^n/2

> 原因：避免新旧序号在窗口中重叠，导致无法区分

### 4.4 确认机制优化

| 机制 | 说明 |
|------|------|
| **累计确认** | 一个ACK确认多个帧，减少确认帧数量 |
| **捎带确认** | 将确认信息附在数据帧中发送 |

## 5. 点对点协议（PPP）

### 5.1 协议特点

**设计目标**：简单、灵活、支持多种网络层协议

**不提供功能**：
- 纠错、流量控制、序号、多点线路、半双工/单工

**三个组成部分：**
1. 将IP数据报封装到串行链路的方法
2. **LCP**（链路控制协议）：建立、配置、测试链路
3. **NCP**（网络控制协议）：配置网络层参数

### 5.2 PPP帧格式

```
┌─────┬─────┬─────┬────────┬──────────┬─────┬─────┐
│  F  │  A  │  C  │ 协议   │  信息    │ FCS │  F  │
│0x7E │0xFF │0x03 │ 2字节  │ ≤1500B  │ 2B  │0x7E │
└─────┴─────┴─────┴────────┴──────────┴─────┴─────┘
```

**协议字段：**
- 0x0021：IP数据报
- 0xC021：LCP数据
- 0x8021：NCP数据

### 5.3 透明传输实现

| 传输方式 | 填充方法 |
|---------|---------|
| **异步传输** | 字符填充：0x7E→0x7D 0x5E；0x7D→0x7D 0x5D |
| **同步传输** | 零比特填充：5个连续1后填0 |

### 5.4 工作状态

```
链路静止 → 链路建立 → 鉴别 → 网络层协议 → 链路打开 → 链路终止
              ↑        ↓        ↓              ↓
              └────────┴────────┴──────────────┘
                (失败/故障时返回)
```

## 6. HDLC协议（高级数据链路控制）

### 6.1 特点

- **面向比特**的同步通信协议
- 由IBM SDLC发展而来，ISO标准化
- 支持全双工通信，可靠性高

### 6.2 帧格式

```
┌─────┬─────┬─────┬────────┬────────┬─────┐
│  F  │  A  │  C  │  Info  │  FCS   │  F  │
│0x7E │ 8位 │ 8位 │ 可变长 │ 16位  │0x7E │
└─────┴─────┴─────┴────────┴────────┴─────┘
```

### 6.3 帧类型（由控制字段C决定）

| 类型 | 格式 | 功能 |
|------|------|------|
| **I帧（信息帧）** | 0 N(S) P/F N(R) | 传输数据，捎带确认 |
| **S帧（监控帧）** | 10 类型 P/F N(R) | 流量控制和差错控制 |
| **U帧（无编号帧）** | 11 M P/F M | 链路控制（建立、拆除等） |

**S帧类型：**
- **RR**（接收准备好）：确认并准备接收
- **RNR**（接收未准备好）：确认但要求暂停
- **REJ**（拒绝）：否定确认，要求重传N及之后帧
- **SREJ**（选择性拒绝）：只要求重传N帧

## 7. 介质访问控制（MAC）

### 7.1 信道分配策略

| 策略 | 代表技术 | 适用场景 |
|------|---------|---------|
| **静态划分** | FDMA、TDMA、CDMA | 用户少且稳定 |
| **动态分配** | ALOHA、CSMA、预约协议 | 用户多且突发 |

**排队论结论**：静态划分信道会增大平均延迟，降低利用率

### 7.2 随机访问协议

**纯ALOHA**
- 想发就发，冲突后随机重发
- 最大效率：**18.4%**（1/2e）

**时隙ALOHA**
- 只能在时隙开始时刻发送
- 最大效率：**36.8%**（1/e）

**CSMA（载波侦听多路访问）**
- 发送前先侦听信道
- 1-坚持：空闲立即发，繁忙持续侦听
- 非坚持：空闲立即发，繁忙随机等待
- p-坚持：空闲以概率p发送

**CSMA/CD（带碰撞检测）**
- 边发送边检测碰撞
- 检测到碰撞立即停止发送（发干扰信号）
- 采用**二进制指数退避算法**确定重传时间

### 7.3 无冲突协议

| 协议 | 机制 | 特点 |
|------|------|------|
| **位图协议** | 预约时隙，按序发送 | 高负载效率高 |
| **令牌传递** | 令牌控制发送权 | 无冲突，公平 |
| **轮询** | 主站轮询从站 | 主从结构 |

### 7.4 有限竞争协议

- 结合竞争协议（低负载好）和无冲突协议（高负载好）
- 将站点分组，各组在不同时隙竞争
- 动态调整竞争站点数，使成功概率最大

## 8. 以太网（Ethernet）

### 8.1 核心技术：CSMA/CD

**关键参数：**
- **争用期**：2τ = 51.2μs（10Mbps）
- **最短帧长**：64字节（确保碰撞时仍在发送）
- **帧间间隔**：9.6μs（96bit时间）

**二进制指数退避算法：**
```
第k次冲突后，从[0, 1, ..., 2^k-1]随机选择r
重传延迟 = r × 2τ
k = min(重传次数, 10)
重传16次仍失败则丢弃
```

**信道利用率：**
```
Smax ≈ 1 / (1 + 4.44a)  （当N→∞时）

其中 a = τ/T0 = (传播时延)/(发送时延)
```

### 8.2 MAC地址

- **48位**（EUI-48），固化在网卡ROM中
- 前24位：OUI（组织唯一标识符，IEEE分配）
- 后24位：扩展唯一标识符（厂商分配）

**地址类型：**
- 单播地址（I/G=0）
- 组播地址（I/G=1）
- 广播地址（全1）

### 8.3 以太网演进

| 标准 | 速率 | 关键改进 |
|------|------|---------|
| 10BASE-T | 10Mbps | 双绞线，星形拓扑 |
| 100BASE-T | 100Mbps | 保持帧格式，缩短争用期 |
| 1000BASE-T | 1Gbps | 载波延伸（512B），帧突发 |
| 10GBASE-T | 10Gbps | 全双工为主，光纤为主 |

**千兆以太网半双工模式：**
- **载波延伸**：短帧填充至512字节
- **帧突发**：一次发送多个帧，提高利用率

## 9. 无线局域网（802.11）

### 9.1 特性与挑战

**与有线链路的区别：**
- 信号强度衰减（路径损耗）
- 干扰（频段共享）
- 多径传播
- **隐蔽节点问题**、**暴露节点问题**

### 9.2 网络结构

| 模式 | 特点 |
|------|------|
| **BSS（基础结构）** | 有AP（接入点），连接有线网络 |
| **Ad hoc** | 无AP，节点自组织网络 |

### 9.3 帧格式

```
┌─────────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬─────────┬─────┐
│ Frame       │ Duration │ Address 1│ Address 2│ Address 3│ Seq      │ Address 4│ Payload  │  CRC    │     │
│ Control     │ /NAV     │ (RA)     │ (TA)     │ (BSSID)  │ Control  │          │          │         │     │
│   2B        │   2B     │   6B     │   6B     │   6B     │   2B     │   6B     │ 0-2312B  │   4B    │     │
└─────────────┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┴─────────┴─────┘
```

**地址说明：**
- Address 1：接收地址（RA）
- Address 2：发送地址（TA）
- Address 3：BSSID（AP的MAC或Ad hoc标识）

### 9.4 MAC协议：CSMA/CA

**为什么不使用CSMA/CD：**
- 无线信号衰减大，难以同时收发检测碰撞
- 存在隐蔽节点问题

**CSMA/CA基本模式：**
```
发送方：                    接收方：
├─侦听信道───────────────┐   │
│  └─空闲≥DIFS───────────┤   │
│     └─发送数据────────→├───┤
│                        │←──┤─等待SIFS─发送ACK
└─收到ACK，成功──────────┘   │
```

**关键时间间隔：**
- **SIFS**（短帧间隔）：最高优先级，用于ACK、CTS
- **PIFS**（PCF帧间隔）：中等优先级
- **DIFS**（DCF帧间隔）：最低优先级，用于数据帧

### 9.5 碰撞避免：RTS-CTS握手

**解决隐蔽节点问题：**
```
A → AP:  RTS (请求发送)
AP → A:  CTS (允许发送)  ← B也能听到，保持静默
A → AP:  DATA
AP → A:  ACK
```

**虚拟载波侦听（NAV）：**
- 从RTS/CTS中提取持续时间字段
- 设置网络分配矢量NAV，指示信道占用时间
- 其他站点根据NAV推迟发送

### 9.6 信道与关联

- **2.4GHz频段**：11个信道（1-11），完全正交：1、6、11
- **被动扫描**：侦听AP的信标帧（Beacon）
- **主动扫描**：发送探测请求，接收探测响应

## 10. 局域网扩展与交换

### 10.1 集线器 vs 交换机

| 特性 | 集线器（Hub） | 交换机（Switch） |
|------|-------------|----------------|
| **工作层次** | 物理层 | 数据链路层 |
| **转发方式** | 广播到所有端口 | 选择性转发到目标端口 |
| **碰撞域** | 一个（共享） | 多个（每个端口独立） |
| **带宽** | 共享 | 独享（全双工） |
| **自学习** | 无 | 有 |

### 10.2 交换机自学习转发

**交换表结构：**（MAC地址，接口，TTL）

**自学习过程：**
1. 收到帧后，记录**源MAC地址**和**输入接口**
2. 查交换表找**目的MAC地址**对应的接口
3. 若找到且接口不同：转发到该接口
4. 若找到但接口相同：丢弃（已在该网段）
5. 若未找到：**泛洪**（转发到除输入外的所有接口）

### 10.3 生成树协议（STP）

**问题**：交换机冗余链路导致环路，帧无限循环

**解决**：构造生成树，阻塞冗余链路
- 网桥交换配置消息（BPDU）
- 选举根网桥（最小MAC地址）
- 计算到根的最短路径
- 阻塞非树链路（逻辑上断开）

### 10.4 虚拟局域网（VLAN）

**作用：**
- 隔离广播域（减少广播流量）
- 安全隔离（不同VLAN不能直接通信）
- 灵活组网（不受物理位置限制）

**实现方式：**
- **基于端口**：交换机端口分组
- **基于MAC地址**：按设备MAC划分

**跨交换机VLAN（802.1Q）：**
- **Access端口**：连接终端，发送无标签帧
- **Trunk端口**：连接交换机，发送带标签帧

**802.1Q帧格式（增加4字节标签）：**
```
┌─────────┬─────────┬─────────┬────────┬─────────┬─────────┐
│ 目的地址 │ 源地址  │ 802.1Q  │  类型   │  数据   │   FCS   │
│  6B     │  6B     │ Tag 4B  │ 2B     │46~1500B │  4B     │
└─────────┴─────────┴─────────┴────────┴─────────┴─────────┘
              ↑
        TPID(2B) + TCI(2B: 优先级3b + CFI1b + VLAN ID12b)
```

## 核心考点小结

1. **成帧与透明传输**：掌握字节填充、零比特填充的原理和计算
2. **差错控制**：CRC计算过程、码距与检错/纠错能力的关系
3. **可靠传输**：停等协议、连续ARQ、选择重传的窗口大小限制和效率计算
4. **MAC协议**：CSMA/CD（以太网）vs CSMA/CA（无线网）的区别
5. **以太网**：最短帧长64B的原因、二进制指数退避、信道利用率公式
6. **无线局域网**：隐蔽/暴露节点问题、RTS-CTS机制、NAV虚拟载波侦听
7. **交换机**：自学习转发原理、生成树协议作用、VLAN标签（802.1Q）
