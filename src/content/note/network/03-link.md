## 数据链路层概述

### 网络体系结构中的位置

**数据链路层的核心地位：**
- 实现**相邻结点**之间的通信
- 网络中的主机、路由器、交换机等都必须实现数据链路层
- 不同链路可采用不同的数据链路层协议

### 基本术语

| 术语 | 定义 |
|------|------|
| **结点(node)** | 主机、路由器等网络设备 |
| **链路(link)** | 连接相邻结点之间的信道（有线/无线） |
| **帧(frame)** | 数据链路层传输的基本单位 |

### 信道类型

| 类型 | 特点 | 协议要求 |
|------|------|----------|
| **点对点信道** | 一对一通信 | 简单，无需协调 |
| **广播信道** | 一对多通信 | 需要专用共享信道协议协调发送 |

### 链路层功能

- **链路管理**：建立、拆除连接（面向连接服务时必须）
- **成帧/解帧**：将数据封装为帧
- **流量控制**：控制发送数据量
- **差错控制**：实现无差错传送
- **透明传输**：希望所有数据都能原样传输，故需要区分数据信息和控制信息
- **寻址**：标识收发双方

### 实现位置：网络适配器（网卡）

```
┌─────────────────────────────────────┐
│  application                        │
│  transport                          │
│  network                            │
│  link ←─────────────────────────┐   │
│  physical                       │   │
│      │                          │   │
│  host bus (e.g., PCI)           │   │
│      │                          │   │
│  ┌─────────────────┐            │   │
│  │  network        │←───────────┘   │
│  │  adapter card   │ controller     │
│  │  (NIC)          │ physical       │
│  └─────────────────┘ transmission   │
│      ↑                              │
│  串/并变换、数据缓存、链路层功能实现   │
└─────────────────────────────────────┘
```

**网卡功能：**
- 发送端：封装成帧、添加校验位和地址、流量控制
- 接收端：检错、地址检查、流量控制、提取数据交高层

**IP与MAC的关系**：IP 地址由网络层使用，MAC 地址由链路层使用。ARP 协议负责 IP 到 MAC 的地址解析。但是两者不是一一对应的。

## 成帧与透明传输

封装成帧就是给数据添加首部和尾部，进行**帧定界**

### 成帧方法

| 方法 | 原理 | 特点 |
|------|------|------|
| **字节计数法** | 头部字段标识帧字节数 | 头部出错则失步 |
| **固定帧长度** | 固定字符长度 | 如 RS232，简单，效率低 |
| **控制字符法** | 使用规定的字符进行帧定界 | 如 HDLC、PPP，但是需要处理透明传输（数据中可能包含规定的字符） |

### 控制字符法详解

#### ASCII 码

ASCII 码分为控制字符和显示字符。若数据是 ASCII 码的，则可以直接利用特殊控制字符 `SOH`/`EOT` 进行帧定界。

**解决透明传输**：
- 发送端：
  - 数据中出现 `SOH` 或 `EOT`，则需在前面插入转义字符 `ESC`（0x1B）
  - 数据中出现 `ESC`，则需在前面再插入一个 `ESC`
- 接收端：向上层传输前删除插入的转义字符，连续的两个只删除一个

```
原始数据: [SOH][A][EOT][B][SOH]
发送数据: [SOH][A][ESC][EOT][B][ESC][SOH][EOT]
```

#### 二进制

若数据是二进制的，则可以直接利用特殊标志 `01111110` 进行帧定界。

**解决透明传输**：
- 发送端：数据中出现5个连续1，立即填入一个0
- 接收端：数据中出现5个连续1，删除后面的0

```
原始数据: 01111110 (恰好为标志位)
发送数据: 011111010 (5个1后填0)
```

## 差错控制

### 定义

**误码率** $P_b$ = 误码位数 / 发送总位数

**无差错帧概率** $P_1 = (1-P_b)^L$ （$L$ 为帧长）

### 差错检测方法

本质上是利用约定关系，由数据位产生**冗余位**，并将数据位和冗余位一起作为**码字**发送。接收方检查数据位和冗余位的关系即可。

分类：
- **检错码**：不能判断错误位的位置
- **纠错码**：能够判断错误位的位置

| 方法 | 类型 | 能力 |
|------|------|------|
| **奇偶校验** | 检错码 | 检测单比特错 |
| **二维奇偶校验** | 纠错码 | 纠正单比特错 |
| **汉明码** | 纠错码 | 纠正单比特错，检测双比特错 |
| **CRC循环冗余校验** | 检错码 | 检测 $\le r$ 位的错 |
| **校验和** | 检错码 | IP/TCP/UDP使用 |
| **交织码** | 检错码 | 将突发错转为随机错 |

### 奇偶校验

**一维**：增加一个冗余位，值为对所有位做异或。

**二维**：将数据列成矩阵，每行每列都计算一个冗余位。右下角还可以增加一个整体校验位。

### CRC 循环冗余校验

**原理：**
- 数据位D（d位）+ 冗余位R（r位）构成码字
- 选择生成多项式G（r+1位）
- 发送端：使<D,R>能被G整除（模2运算）
- 接收端：<D,R>除以G，余数为0则无错

**计算过程：**
```
数据D = 1010001101 (d=10位)
生成式G = 110101 (r+1=6位，即r=5)

计算：2^5 × D ÷ G 得余数R
      101000110100000 ÷ 110101 = 商...余数01110

发送数据：1010001101 01110 (D后附加R)
```

**注**：是多项式除法！所以不能借位，并且是环上的加减法

**典型生成多项式：**
- CRC-16：X^16 + X^15 + X^2 + 1
- CRC-CCITT：X^16 + X^12 + X^5 + 1
- CRC-32：用于以太网

**CRC特点：**
- 能检出所有 1 比特错、2 比特错、奇数位错
- 能检出所有≤r位的突发错
- 易于硬件实现（移位寄存器）

### 码距与编码效率

- **码距**：两个码字中不相同位的个数
- **检错能力**：要检测d位错，需码距≥d+1
- **纠错能力**：要纠正d位错，需码距≥2d+1
- **码率** = m/n（m位信息，n位码长）

> **重要区分**：CRC只能实现"无差错接受"（丢弃错误帧），不能实现"可靠传输"。可靠传输需要确认和重传机制（ARQ）。

## 可靠传输与流量控制

差错控制负责丢帧，链路层协议负责处理丢帧以及流量控制。

帧可能遇到的**异常**：
1. 帧丢失
2. 帧迟到
3. 帧损坏
4. 帧重复
5. 帧失序

### 停等 ARQ

#### 工作原理
- 发送方每次发送一帧 $i$
- 接收方每次接收一帧 $i$，并发送确认帧
- 发送方收到确认帧后再发送下一帧 $i+1$

#### 关键机制
- **超时重传**：
  发送方发送后启动定时器，超时未收到确认则重传。主要解决发送帧丢失、确认帧丢失、帧损坏等异常。
- **序号机制**：
  数据帧和确认帧都带 1 比特序号（0/1 交替），从而可以分辨新旧帧（因为最多只会涉及 2 帧故只需 1 位）。主要解决发送帧迟到、确认帧迟到、帧重复等异常。
- **重复帧处理**：接收方丢弃重复帧，并重传确认。主要解决发送帧迟到、帧重复等异常。

#### 信道利用率[^1]

$$
U = \frac{t_{send-data}}{RTT} = \frac{1}{1 + 2 \alpha}
$$
其中 $\alpha = \frac{t_{trans}}{t_{send}}$（后一个等式假设 $t_{send_ack}$ 可忽略且对称链路）。

[^1]: 发送端占用信道传输数据的时间比例。

**性能问题**：长时延，信道利用率低（如卫星通信）

### 连续 ARQ

#### 工作原理

- 发送方连续发送 $w$ 个帧 $[i, i + w - 1]$，并为第一帧设置**超时计时器**
- 接收方按序接收一帧，并发送确认帧
- 发送方接收到确认帧 $j$（$i \le j \le i + w - 1$）时，取消对帧 $j$ 的计时器，并调整发送窗口为 $[j + 1, j + w]$，同时发送窗口内的新帧 $[i + w, j + w]$
- 若发送方的帧 $i$ 计时器超时（一定是第一帧超时），则重传 $[i, i + w - 1]$

#### 关键机制

- **单一计时器**：
  只为窗口左沿的帧设置计时器。事实上，为每一帧都设置是没必要的，因为越先发送的帧越先超时。


- 

#### 信道利用率

$$
U = 
\begin{cases}
\frac{w}{1 + 2 \alpha}, \qquad w \lt 1 + 2 \alpha \\
1, \qquad w \ge 1 + 2 \alpha
\end{cases}
$$

- **累计确认**：
  收到确认帧 $j$ 则意味着 $j$ 及以前的所有帧都被接收，从而可以减少确认帧的发送开销。

### 分类

本质上都是滑动窗口协议。

按照发送窗口大小 $w_{send}$ 和接收窗口大小 $w_{rcvd}$，又分为停等 ARQ（$w_{send} = 1$，$w_{rcvd} = 1$）、连续 ARQ（$w_{send} \gt 1$，$w_{rcvd} = 1$）和选择重传 ARQ（$w_{send} \gt 1$，$w_{rcvd} \gt 1$）。

三者的具体实现方式是停等协议、go back n、selective repeat。

### 确认机制优化

- **累计确认**：一个 ACK 确认多个帧，减少确认帧数量
- **捎带确认**：将确认信息附在数据帧中发送

## 点对点协议（PPP）

我们需要设计协议建立、封装和配置链路。

### 协议特点

**设计目标**：简单、灵活、支持多种网络层协议

只提供**成帧**和**检错**，不提供纠错、流量控制、序号、多点线路、半双工/单工

**三个组成部分：**
1. 将IP数据报封装到串行链路的方法
2. **LCP**（链路控制协议）：建立、配置、测试链路
3. **NCP**（网络控制协议）：配置网络层参数

### PPP 帧格式

```
┌─────┬─────┬─────┬────────┬──────────┬─────┬─────┐
│  F  │  A  │  C  │protocal│   data   │ FCS │  F  │
│0x7E │0xFF │0x03 │   2B   │  ≤1500B  │ 2B  │0x7E │
└─────┴─────┴─────┴────────┴──────────┴─────┴─────┘
```

**协议字段：**
- 0x0021：IP数据报
- 0xC021：LCP数据
- 0x8021：NCP数据

### 透明传输实现

| 传输方式 | 填充方法 |
|---------|---------|
| **异步传输** | 字符填充：0x7E→0x7D 0x5E；0x7D→0x7D 0x5D |
| **同步传输** | 零比特填充：5个连续1后填0 |

### 工作状态

```
链路静止 → 链路建立 → 鉴别 → 网络层协议 → 链路打开 → 链路终止
              ↑        ↓        ↓              ↓
              └────────┴────────┴──────────────┘
                         (失败/故障时返回)
```

## HDLC协议（高级数据链路控制）

### 特点

- **面向比特**的同步通信协议
- 由IBM SDLC发展而来，ISO标准化
- 支持全双工通信，可靠性高

### 帧格式

```
┌─────┬─────┬─────┬────────┬────────┬─────┐
│  F  │  A  │  C  │  Info  │  FCS   │  F  │
│0x7E │ 8位 │ 8位 │ 可变长 │ 16位  │0x7E │
└─────┴─────┴─────┴────────┴────────┴─────┘
```

### 帧类型（由控制字段C决定）

| 类型 | 格式 | 功能 |
|------|------|------|
| **I帧（信息帧）** | 0 N(S) P/F N(R) | 传输数据，捎带确认 |
| **S帧（监控帧）** | 10 类型 P/F N(R) | 流量控制和差错控制 |
| **U帧（无编号帧）** | 11 M P/F M | 链路控制（建立、拆除等） |

**S帧类型：**
- **RR**（接收准备好）：确认并准备接收
- **RNR**（接收未准备好）：确认但要求暂停
- **REJ**（拒绝）：否定确认，要求重传N及之后帧
- **SREJ**（选择性拒绝）：只要求重传N帧

## 介质访问控制（MAC）

饱和、公平、分布

### 信道分配策略

| 策略 | 代表技术 | 适用场景 |
|------|---------|---------|
| **静态划分** | FDMA、TDMA、CDMA | 用户少且稳定 |
| **动态分配** | ALOHA、CSMA、预约协议 | 用户多且突发 |

**排队论结论**：静态划分信道会增大平均延迟，降低利用率

### 随机访问协议

**纯ALOHA**
- 想发就发，冲突后随机重发
- 最大效率：**18.4%**（1/2e）

**时隙ALOHA**
- 只能在时隙开始时刻发送
- 最大效率：**36.8%**（1/e）

**CSMA（载波侦听多路访问）**
- 发送前先侦听信道
- 1-坚持：空闲立即发，繁忙持续侦听
- 非坚持：空闲立即发，繁忙随机等待
- p-坚持：空闲以概率p发送

**CSMA/CD（带碰撞检测）**
- 边发送边检测碰撞
- 检测到碰撞立即停止发送（发干扰信号）
- 采用**二进制指数退避算法**确定重传时间

### 无冲突协议

| 协议 | 机制 | 特点 |
|------|------|------|
| **位图协议** | 预约时隙，按序发送 | 高负载效率高 |
| **令牌传递** | 令牌控制发送权 | 无冲突，公平 |
| **轮询** | 主站轮询从站 | 主从结构 |

### 有限竞争协议

- 结合竞争协议（低负载好）和无冲突协议（高负载好）
- 将站点分组，各组在不同时隙竞争
- 动态调整竞争站点数，使成功概率最大

## 8. 以太网（Ethernet）

### 8.1 核心技术：CSMA/CD

**关键参数：**
- **争用期**：2τ = 51.2μs（10Mbps）
- **最短帧长**：64字节（确保碰撞时仍在发送）
- **帧间间隔**：9.6μs（96bit时间）

**二进制指数退避算法：**
```
第k次冲突后，从[0, 1, ..., 2^k-1]随机选择r
重传延迟 = r × 2τ
k = min(重传次数, 10)
重传16次仍失败则丢弃
```

**信道利用率：**
```
Smax ≈ 1 / (1 + 4.44a)  （当N→∞时）

其中 a = τ/T0 = (传播时延)/(发送时延)
```

### 8.2 MAC地址

- **48位**（EUI-48），固化在网卡ROM中
- 前24位：OUI（组织唯一标识符，IEEE分配）
- 后24位：扩展唯一标识符（厂商分配）

**地址类型：**
- 单播地址（I/G=0）
- 组播地址（I/G=1）
- 广播地址（全1）

### 8.3 以太网演进

| 标准 | 速率 | 关键改进 |
|------|------|---------|
| 10BASE-T | 10Mbps | 双绞线，星形拓扑 |
| 100BASE-T | 100Mbps | 保持帧格式，缩短争用期 |
| 1000BASE-T | 1Gbps | 载波延伸（512B），帧突发 |
| 10GBASE-T | 10Gbps | 全双工为主，光纤为主 |

**千兆以太网半双工模式：**
- **载波延伸**：短帧填充至512字节
- **帧突发**：一次发送多个帧，提高利用率

## 9. 无线局域网（802.11）

### 9.1 特性与挑战

**与有线链路的区别：**
- 信号强度衰减（路径损耗）
- 干扰（频段共享）
- 多径传播
- **隐蔽节点问题**、**暴露节点问题**

### 9.2 网络结构

| 模式 | 特点 |
|------|------|
| **BSS（基础结构）** | 有AP（接入点），连接有线网络 |
| **Ad hoc** | 无AP，节点自组织网络 |

### 9.3 帧格式

```
┌─────────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬─────────┬─────┐
│ Frame       │ Duration │ Address 1│ Address 2│ Address 3│ Seq      │ Address 4│ Payload  │  CRC    │     │
│ Control     │ /NAV     │ (RA)     │ (TA)     │ (BSSID)  │ Control  │          │          │         │     │
│   2B        │   2B     │   6B     │   6B     │   6B     │   2B     │   6B     │ 0-2312B  │   4B    │     │
└─────────────┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┴─────────┴─────┘
```

**地址说明：**
- Address 1：接收地址（RA）
- Address 2：发送地址（TA）
- Address 3：BSSID（AP的MAC或Ad hoc标识）

### 9.4 MAC协议：CSMA/CA

**为什么不使用CSMA/CD：**
- 无线信号衰减大，难以同时收发检测碰撞
- 存在隐蔽节点问题

**CSMA/CA基本模式：**
```
发送方：                    接收方：
├─侦听信道───────────────┐   │
│  └─空闲≥DIFS───────────┤   │
│     └─发送数据────────→├───┤
│                        │←──┤─等待SIFS─发送ACK
└─收到ACK，成功──────────┘   │
```

**关键时间间隔：**
- **SIFS**（短帧间隔）：最高优先级，用于ACK、CTS
- **PIFS**（PCF帧间隔）：中等优先级
- **DIFS**（DCF帧间隔）：最低优先级，用于数据帧

### 9.5 碰撞避免：RTS-CTS握手

**解决隐蔽节点问题：**
```
A → AP:  RTS (请求发送)
AP → A:  CTS (允许发送)  ← B也能听到，保持静默
A → AP:  DATA
AP → A:  ACK
```

**虚拟载波侦听（NAV）：**
- 从RTS/CTS中提取持续时间字段
- 设置网络分配矢量NAV，指示信道占用时间
- 其他站点根据NAV推迟发送

### 9.6 信道与关联

- **2.4GHz频段**：11个信道（1-11），完全正交：1、6、11
- **被动扫描**：侦听AP的信标帧（Beacon）
- **主动扫描**：发送探测请求，接收探测响应

## 10. 局域网扩展与交换

### 10.1 集线器 vs 交换机

| 特性 | 集线器（Hub） | 交换机（Switch） |
|------|-------------|----------------|
| **工作层次** | 物理层 | 数据链路层 |
| **转发方式** | 广播到所有端口 | 选择性转发到目标端口 |
| **碰撞域** | 一个（共享） | 多个（每个端口独立） |
| **带宽** | 共享 | 独享（全双工） |
| **自学习** | 无 | 有 |

### 10.2 交换机自学习转发

**交换表结构：**（MAC地址，接口，TTL）

**自学习过程：**
1. 收到帧后，记录**源MAC地址**和**输入接口**
2. 查交换表找**目的MAC地址**对应的接口
3. 若找到且接口不同：转发到该接口
4. 若找到但接口相同：丢弃（已在该网段）
5. 若未找到：**泛洪**（转发到除输入外的所有接口）

### 10.3 生成树协议（STP）

**问题**：交换机冗余链路导致环路，帧无限循环

**解决**：构造生成树，阻塞冗余链路
- 网桥交换配置消息（BPDU）
- 选举根网桥（最小MAC地址）
- 计算到根的最短路径
- 阻塞非树链路（逻辑上断开）

### 10.4 虚拟局域网（VLAN）

**作用：**
- 隔离广播域（减少广播流量）
- 安全隔离（不同VLAN不能直接通信）
- 灵活组网（不受物理位置限制）

**实现方式：**
- **基于端口**：交换机端口分组
- **基于MAC地址**：按设备MAC划分

**跨交换机VLAN（802.1Q）：**
- **Access端口**：连接终端，发送无标签帧
- **Trunk端口**：连接交换机，发送带标签帧

**802.1Q帧格式（增加4字节标签）：**
```
┌─────────┬─────────┬─────────┬────────┬─────────┬─────────┐
│ 目的地址 │ 源地址  │ 802.1Q  │  类型   │  数据   │   FCS   │
│  6B     │  6B     │ Tag 4B  │ 2B     │46~1500B │  4B     │
└─────────┴─────────┴─────────┴────────┴─────────┴─────────┘
              ↑
        TPID(2B) + TCI(2B: 优先级3b + CFI1b + VLAN ID12b)
```

## 核心考点小结

1. **成帧与透明传输**：掌握字节填充、零比特填充的原理和计算
2. **差错控制**：CRC计算过程、码距与检错/纠错能力的关系
3. **可靠传输**：停等协议、连续ARQ、选择重传的窗口大小限制和效率计算
4. **MAC协议**：CSMA/CD（以太网）vs CSMA/CA（无线网）的区别
5. **以太网**：最短帧长64B的原因、二进制指数退避、信道利用率公式
6. **无线局域网**：隐蔽/暴露节点问题、RTS-CTS机制、NAV虚拟载波侦听
7. **交换机**：自学习转发原理、生成树协议作用、VLAN标签（802.1Q）
